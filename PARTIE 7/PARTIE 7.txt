👉 Les chemins relatifs : la règle d'or
---------------------
<!-- Dans index.html -->

<!-- MAUVAIS — chemin absolu (ne fonctionne qu'en local) -->
<link rel="stylesheet" href="/Users/alice/projets/calculateur/style.css">
<script src="C:\projets\calculateur\script.js"></script>

<!-- MAUVAIS — chemin absolu depuis la racine (casse sur GitHub Pages) -->
<link rel="stylesheet" href="/style.css">

<!-- CORRECT — chemin relatif (fonctionne partout) -->
<link rel="stylesheet" href="style.css">
<script src="script.js"></script>

<!-- CORRECT — sous-dossier -->
<link rel="stylesheet" href="css/style.css">
<script src="js/script.js"></script>
---------------------


👉 La checklist de déploiement
---------------------
CHECKLIST AVANT DÉPLOIEMENT
─────────────────────────────────────────────────────────

[  ] Le fichier principal est nommé index.html
[  ] Tous les liens CSS utilisent des chemins relatifs
[  ] Tous les liens JS utilisent des chemins relatifs
[  ] Les images (si présentes) utilisent des chemins relatifs
[  ] L'application fonctionne localement (ouvrir index.html dans le navigateur)
[  ] La console DevTools ne montre aucune erreur rouge
[  ] Les API externes utilisent HTTPS (pas HTTP)
[  ] Les clés API sont placées dans des variables (jamais dans le HTML)
[  ] Le titre de la page (<title>) est descriptif
[  ] La balise <meta name="viewport"> est présente (pour mobile)

✅ 8.2 — Guide GitHub Pages : configuration du dépôt, branche gh-pages, URL en ligne


👉 Installer Git en local
---------------------
# Vérifier si Git est installé
git --version
# Exemple de retour : git version 2.43.0

# Si Git n'est pas installé :
# Windows : https://git-scm.com/download/win
# macOS   : xcode-select --install (installe aussi Xcode Command Line Tools)
# Linux   : sudo apt install git

# Configurer votre identité (une seule fois)
git config --global user.name "Alice Martin"
git config --global user.email "alice.martin@email.com"
---------------------


👉 Créer et pousser un dépôt pour chaque projet
---------------------
# ÉTAPE 1 — Créer le dépôt sur GitHub
# Allez sur github.com → bouton "+" en haut à droite → "New repository"
# Nom du dépôt : calculateur-pourboire
# Visibilité : Public (obligatoire pour GitHub Pages gratuit)
# Ne cochez PAS "Initialize this repository with a README" (on le fait manuellement)
# Cliquez "Create repository"

# ÉTAPE 2 — Initialiser Git dans votre dossier projet
cd /chemin/vers/calculateur-pourboire
git init

# ÉTAPE 3 — Ajouter tous les fichiers
git add .

# ÉTAPE 4 — Créer le premier commit
git commit -m "Initial commit : calculateur de pourboire complet"

# ÉTAPE 5 — Relier votre dossier local au dépôt GitHub
# Remplacez alice-martin par votre nom d'utilisateur GitHub
git remote add origin https://github.com/alice-martin/calculateur-pourboire.git

# ÉTAPE 6 — Pousser le code vers GitHub
git branch -M main
git push -u origin main
---------------------


👉 Activer GitHub Pages
---------------------
1. Ouvrez votre dépôt sur github.com
   Exemple : https://github.com/alice-martin/calculateur-pourboire

2. Cliquez sur l'onglet "Settings" (en haut du dépôt)

3. Dans le menu de gauche, cliquez "Pages"

4. Sous "Branch", sélectionnez "main" dans le menu déroulant
   Laissez le dossier sur "/ (root)"

5. Cliquez "Save"

6. Attendez 60 à 120 secondes (GitHub construit et déploie votre site)

7. Actualisez la page Settings > Pages
   Vous verrez un bandeau vert :
   "Your site is live at https://alice-martin.github.io/calculateur-pourboire/"
---------------------


👉 Mettre à jour votre application déployée
---------------------
# Depuis le dossier de votre projet, après vos modifications :

# 1. Voir quels fichiers ont changé
git status

# 2. Ajouter tous les fichiers modifiés
git add .

# 3. Créer un commit avec un message descriptif
git commit -m "Amélioration : ajout de la validation des entrées vides"

# 4. Pousser vers GitHub (et donc mettre à jour le site)
git push

# Le site est mis à jour en moins d'une minute.

✅ 8.3 — Déploiement avec Netlify : glisser-déposer, bases du domaine personnalisé


👉 Méthode 1 : le glisser-déposer (la plus rapide)
---------------------
DÉPLOIEMENT PAR GLISSER-DÉPOSER
─────────────────────────

1. Connectez-vous sur app.netlify.com

2. Sur le tableau de bord, vous verrez une zone :"
   "Want to deploy a new site without connecting to Git?"
   "Drag and drop your site output folder here"

3. Ouvrez l'Explorateur de fichiers (Windows) ou le Finder (macOS)

4. Naviguez jusqu'au dossier de votre projet
   Par exemple : Documents/projets/calculateur-pourboire/

5. Faites glisser le DOSSIER (pas les fichiers individuels) dans la zone Netlify

6. Attendez 10 à 15 secondes

7. Netlify génère une URL aléatoire de type :
   https://charming-madeleine-4a2f1b.netlify.app
   Votre application est en ligne !
---------------------


👉 Méthode 2 : déploiement continu depuis GitHub (recommandé)
---------------------
CONNEXION NETLIFY — GITHUB (DÉPLOIEMENT CONTINU)
──────────────────────────────

1. Sur app.netlify.com, cliquez "Add new site" → "Import an existing project"

2. Cliquez "Deploy with GitHub"
   Autorisez Netlify à accéder à vos dépôts si demandé

3. Cherchez et sélectionnez votre dépôt (ex: calculateur-pourboire)

4. Configuration du déploiement :
   Branch to deploy : main
   Build command    : (laisser vide — pas de build pour du JavaScript pur)
   Publish directory: . (point — la racine du dépôt)

5. Cliquez "Deploy calculateur-pourboire"

6. Netlify déploie en quelques secondes.
   À chaque git push, le site se met à jour automatiquement.
---------------------


👉 Ajouter un domaine personnalisé (bases)
---------------------
CONNECTER UN DOMAINE PERSONNALISÉ SUR NETLIFY
────────────────────────────

1. Dans le tableau de bord de votre site Netlify,
   cliquez "Domain settings" → "Add custom domain"

2. Entrez votre domaine : alicemartin.dev (sans https://)

3. Netlify vous donne les informations DNS à configurer chez votre registrar :
   Type : A    Nom : @    Valeur : 75.2.60.5
   Type : CNAME Nom : www  Valeur : votre-site.netlify.app

4. Connectez-vous chez votre registrar (OVH, Gandi, Namecheap...)
   et ajoutez ces enregistrements DNS

5. Attendez 5 à 60 minutes (propagation DNS)

6. De retour sur Netlify, cliquez "Verify DNS configuration"
   puis "Enable HTTPS" → "Provision certificate"

7. Votre site est accessible sur https://alicemartin.dev avec HTTPS actif.

# Tableau Kanban — Gestion de tâches

> Application web de gestion de tâches avec glisser-déposer et persistance des données.
> Construite en JavaScript pur, sans framework.

## Démonstration en ligne

🔗 [Voir l'application](https://alice-martin.github.io/kanban/)

## Fonctionnalités

- Trois colonnes (À faire / En cours / Terminé)
- Déplacement de cartes par glisser-déposer (API Drag and Drop native)
- Ajout et suppression de cartes avec confirmation
- Priorité visuelle par couleur (haute / moyenne / basse)
- Persistance des données avec localStorage (survit au rechargement)

## Technologies utilisées

- HTML5 / CSS3 (Flexbox)
- JavaScript ES6+ (sans dépendances)
- API Drag and Drop
- localStorage + JSON

## Concepts JavaScript appris

- Gestion d'état centralisé
- Sérialisation / désérialisation JSON
- Délégation d'événements
- Génération dynamique du DOM

## Lancer le projet en local

```bash
git clone https://github.com/alice-martin/kanban.git
cd kanban
npx serve .
```

👉 Étape suivante recommandée : React
---------------------
POURQUOI REACT APRÈS CE LIVRE ?
───────────────────

Votre application météo vous a appris l'asynchrone → React use les mêmes Promises

Votre calculateur de pourboire vous a appris les events → React a des onClick, onChange

Votre flashcard app vous a appris l'état → React a useState() qui fait exactement ça

Votre Kanban vous a appris le rendu depuis l'état → React est construit sur ce principe

La différence : React automatise le re-rendu efficacement.
Vous en avez déjà compris le POURQUOI.

👉 Étape parallèle : TypeScript
---------------------
// JavaScript (ce que vous écrivez maintenant)
function calculerPourboire(montant, pourcentage) {
  return montant * (pourcentage / 100);
}

// TypeScript (le même, avec des types)
function calculerPourboire(montant: number, pourcentage: number): number {
  return montant * (pourcentage / 100);
}

// Avantage : TypeScript signale une erreur immédiatement si vous appelez
// calculerPourboire("dix", 15)  ← erreur détectée avant l'exécution
---------------------
